TREND DETECTIVE - DATA SOURCES, API CALLS AND AI MODELS

This is the project inventory as of V2 planning. “In use” means the current code calls or reads the source.
“Planned” means it is part of the V2 plan but must not be claimed as a working user feature until it is tested.
“Reference only” means it is documented for future work or user learning, not fetched by the app.

====================================================================
1. EARTH-SCIENCE AND CLIMATE DATA IN USE
====================================================================

NASA POWER
Provider: NASA Langley Research Center (LaRC) POWER Project
API: https://power.larc.nasa.gov/api/temporal/monthly/point
Use: Main historical monthly point data. The app calculates annual values, trends, anomalies, local analysis grids and monthly forecast inputs from it.
Examples of variables: air temperature, daily high/low temperature, ground temperature, rainfall/snowfall, humidity, water vapour, soil wetness, evaporation, cloud cover, sunlight/radiation, wind and pressure.
Data type: NASA POWER blends reanalysis/model data with satellite and ground observations. It is not a street-level measurement.

NASA GISS GISTEMP v4
Provider: NASA Goddard Institute for Space Studies
Use: Global surface-temperature and latitude-band data for Planet Vitals and independent temperature context.

NOAA Global Monitoring Laboratory
Provider: NOAA GML
Use: Atmospheric carbon-dioxide series for Planet Vitals.

NSIDC Sea Ice Index
Provider: National Snow and Ice Data Center / NOAA@NSIDC
Use: Arctic and Antarctic sea-ice extent for Planet Vitals.

NOAA Climate Prediction Center and NOAA National Centers for Environmental Information
Providers: NOAA CPC and NCEI
Use: ENSO, Pacific Decadal Oscillation and North Atlantic Oscillation status/context series.

Natural Earth / world-atlas
Provider: Natural Earth public-domain map data, packaged by world-atlas
Use: Land, borders and globe geography. This is map geometry, not Earth-system data.

2. WEATHER AND NEWS APIS
====================================================================

Meteomatics Weather API - PLANNED/OPTIONAL V2 LIVE FEATURE
Provider: Meteomatics
API pattern: https://api.meteomatics.com/{validdatetime}/{parameters}/{locations}/json
Authentication: Server-only username/password from METEOMATICS_USERNAME and METEOMATICS_PASSWORD. Never sent to the browser.
Use: Current and short-range (1–72 hour) operational weather at a chosen location.
Initial parameters:
- t_2m:C - 2 metre air temperature in Celsius
- precip_1h:mm - hourly precipitation in millimetres
- total_cloud_cover:p - total cloud cover in percent
- wind_speed_10m:ms - 10 metre wind speed in metres per second
Important label: Meteomatics weather is separate from NASA historical trend/reanalysis data and from Trend Detective’s own monthly forecast.

GDELT DOC API - PLANNED/OPTIONAL V2 NEWS FEATURE
Provider: GDELT Project
Use: Environmental/weather news context for selected saved locations. The backend deduplicates results, assigns a transparent green/amber/red attention label and has stale/empty fallbacks.
Important label: News is context, not scientific evidence. An article does not prove a climate cause or make a trend statistically significant.

Optional configurable news feed
Use: The backend also has a configurable JSON news-provider adapter for a future approved provider/API key.
Status: Not configured by default. Any provider needs source/terms review and an explicit publisher trust signal.

3. AI API AND AI MODELS
====================================================================

OpenAI Responses API - PLANNED/OPTIONAL V2 WHY FEATURE
Provider: OpenAI
Endpoint family: Responses API, server-side only
Authentication: OPENAI_API_KEY in local backend environment or Azure App Service application settings. Never in frontend code.
Use: When a user manually clicks “Why might this be happening?”, the backend sends verified trend facts to the model. It returns possible explanations, limitations and cited sources.
Safety rules: The AI cannot calculate or alter statistics, prove a cause, invent citations, or give emergency/medical/legal advice. If no key/service/citations are available, the app returns curated scientific context or an honest unavailable state.
Web search: Must use the current Responses `web_search` tool with domain filters after the backend repair. Web search is only called manually, not automatically, and responses are cached to control cost.
Model choice: OPENAI_EXPLANATION_MODEL is configurable. Use a currently supported low-cost model available to the project account, after a small real-key smoke test. Do not hard-code an obsolete model name.

4. INTERNAL ANALYSIS AND FORECAST MODELS
====================================================================

Trend statistics
Use: Hand-written Python implementations, audited against scientific/reference libraries. Includes Theil–Sen slope and confidence interval, Mann–Kendall test, regression t-test, serial-correlation adjustment, Benjamini–Hochberg false-discovery control, Pettitt change-point check and evidence grade.

Existing annual forecast lab
Use: Backtested annual forecasts using naive baselines, trend models, ridge regression and an ensemble. It withholds claims when no model beats a naive baseline.

V2 monthly forecast
Use: 1–3 month forecasts for T2M, PRECTOTCORR and CLOUD_AMT on a small NASA POWER local grid.
Candidates: seasonal-naive baseline, harmonic/damped-trend approach and regularised autoregressive approach.
Quality gate: The selected model must beat seasonal naive across all requested horizons and pass calibration/coverage checks. If it fails, no future frames are displayed.
